## ArtCraftをインストールすると得られるもの

ArtCraftは、単一のクラウドエンドポイントを薄くラップしたものではありません。これはプロジェクト自身の言葉を借りればクラフティングエンジンであり、出力を賭け事に任せるのではなく操縦したいアーティスト、デザイナー、映像制作者を対象としています。デスクトップ優先の設計により、作業は自分が所有するハードウェア上で行われ、ファイルは置いた場所にそのまま残ります。

| 機能 | できること | 最も恩恵を受ける人 |
|---|---|---|
| オープンソースのコードベース | コードを検査、フォーク、拡張できる | 開発者、コンプライアンス規則のあるスタジオ |
| デスクトップネイティブアプリ | ブラウザタブではなくローカルアプリケーションとして動作 | 大きなファイルや遅いアップロードを扱う人 |
| 画像生成 | プロンプトと参照画像から静止画を生成 | コンセプトアーティスト、イラストレーター、アートディレクター |
| 動画生成 | プロンプトと参照画像をモーションクリップに変換 | 映像制作者、モーションデザイナー、ストーリーボーダー |
| プロンプト制御 | 構図とスタイルをきめ細かく指示 | 終わりのない再生成に疲れたクリエイター |
| 参照画像駆動のワークフロー | ソース画像で出力を導く | キャラクター、ブランド、スタイルの一貫性 |
| モデルの柔軟性 | 高速動画向けのSeedance 2.0を含むモデルをサポート | スピードを追う動画優先のクリエイター |

一貫しているのはコントロールです。クラウドツールは利便性を最適化し、ArtCraftは意図を最適化します。偶然に美しいものを生成し、その後再現できなかったことがあるなら、そのギャップこそ、オープンなデスクトップワークフローが埋めるために作られたものです。

## ステップバイステップ：ArtCraftのダウンロードを完了し、初回セットアップを行う

インストーラーを手に取る前に、以下のチェックリストに5分費やしてください。失敗したセットアップのほとんどは、アプリ自体ではなく、このリストにある何かに起因します。

| 確認項目 | 重要な理由 | 確認方法 |
|---|---|---|
| プラットフォームビルド | デスクトップアプリはOSごとに配布される | 公式ダウンロードページで自分のOSを確認する |
| 空きストレージ | モデルとレンダー出力はかなりの容量を消費する | 対象ドライブの空き容量を確認する |
| GPU性能 | 動画生成は計算負荷が高い | GPUモデルと利用可能なVRAMを確認する |
| 最新のドライバー | 古いGPUドライバーはクラッシュの主要因 | ベンダーの更新ツールを実行する |
| 安定した接続 | セットアップ中にモデルファイルをダウンロードする | 有線または強いWi-Fiを優先する |
| アカウントアクセス | 一部の機能とモデルアクセスにはサインインが必要 | 起動前に認証情報を用意する |

それらを片付ければ、インストール自体は簡単です。

| ステップ | 操作 | 期待されること |
|---|---|---|
| 1 | ダウンロードの公式ソースへ行く | サードパーティのミラーやバンドルインストーラーを避ける |
| 2 | 自分のオペレーティングシステム用のビルドを選択する | 単一のインストーラーまたはアーカイブファイル |
| 3 | 実行する前にファイルを検証する | ファイル名とサイズが公式の掲載内容と一致する |
| 4 | インストーラーを実行するかアーカイブを展開する | 標準的なOSのインストールプロンプト |
| 5 | アプリを起動し、求められたらサインインする | メインワークスペースが開く |
| 6 | モデルをダウンロードまたは選択する | ファイルがローカルに保存される間、進行状況が表示される |
| 7 | 小さなテストレンダーを実行する | 素早い低解像度画像または短いクリップ |
| 8 | 専用の出力フォルダーを設定する | レンダーが期待した場所に保存される |

7番目のステップは、多くの人が飛ばしてしまうものです。安価なテストレンダーは、ヒーローショットに1時間を費やす前に、モデル、ハードウェア、出力パスというチェーン全体を確認します。

### ArtCraftのダウンロードに関するトラブルシューティング

| 症状 | 考えられる原因 | 解決策 |
|---|---|---|
| インストーラーがブロックまたは隔離される | OSのセキュリティが未知のファイルにフラグを立てる | セキュリティ設定で許可してから再実行する |
| アプリが開いてすぐ閉じる | GPUドライバーの不一致またはランタイム不足 | ドライバーを更新し、再起動して再度起動する |
| レンダーが遅い | モデルがハードウェアに対して重すぎる | 解像度を下げ、クリップを短くし、ステップを減らす |
| モデルのダウンロードが止まる | ネットワーク中断 | 一時停止して再開するか、有線接続に切り替える |
| 出力がプロンプトを無視する | プロンプトが曖昧すぎる、参照画像がない | 参照画像を追加し、具体的にする |
| 完成したレンダーが見つからない | デフォルトの出力場所 | プロジェクトフォルダーを割り当てて確認する |

コミュニティの報告は一貫して同じパターンを指摘しています。ドライバーの更新と出力フォルダーの規律が、初日の問題の大半を解決します。

## ArtCraftのダウンロード後に良い結果を得るためのヒント

アプリをインストールするのは簡単な部分です。実際にポートフォリオに入れたい出力を得るには、方法論が必要です。

- **プロンプトを層にする。** 被写体、次にスタイル、次にライティング、次にカメラを記述します。曖昧なプロンプトは曖昧なフレームを生みます。
- **参照画像を先に使う。** 強い参照画像1枚は、3段落の説明よりも多くのことをしてくれることがよくあります。
- **小さく反復し、大きく仕上げる。** 低解像度で構図を固め、その後、品質を上げる価値のあるフレームだけを高品質にします。
- **プロンプトジャーナルを付ける。** 設定を含め、うまくいったことを記録します。再現性はローカルワークフローの最大の目的です。
- **プロジェクトごとに整理する。** プロジェクトごとに1つのフォルダーを作り、参照用と書き出し用のサブフォルダーを用意します。
- **意図的に更新する。** オープンソースプロジェクトは動きが速いため、プロジェクト途中で更新する前にリリースノートを読みます。
- **一度に1つの変数だけテストする。** モデル、プロンプト、参照画像を変更する — 一度に3つすべてを変えないでください。

| 習慣 | 短期的なコスト | 長期的な見返り |
|---|---|---|
| プロンプトの記録 | セッションごとに数分 | 実証済みプロンプトの再利用可能なライブラリ |
| 参照フォルダー | 最初のセットアップ時間 | 一貫したキャラクターとブランドルック |
| 低解像度での反復 | 開始が少し遅くなる | 無駄な高品質レンダーが減る |
| プロジェクトベースのファイル構造 | 規律 | 数か月後でも何でも見つけられる |

クラウドツールから来た人にとって最大の調整は、責任が自分に移ることです。悪いプロンプトのためのサポート窓口はありません — しかし、実験中に走り続けるクレジットメーターもありません。ArtCraftのダウンロードが動作し始めれば、もう1つアイデアを試す限界費用はほぼゼロになり、それがどれだけ自由に探索するかを変えます。

## よくある質問

**ArtCraftのダウンロードは無料で使えますか？**
ArtCraftはオープンソースのデスクトップアプリケーションです。つまり、コードは公開されており、あなたは自分のコピーを所有します。ライセンスの詳細や特定のモデルに関連する費用は変更される可能性があるため、ワークフローに本格的に取り組む前に公式サイトで現在の条件を確認してください。

**ArtCraftでは実際に何を作れますか？**
このアプリはAI画像生成とAI動画生成の両方をカバーします。ほとんどのアーティストは、ルックを調整するために静止画から始め、プロンプトと参照画像が一貫した結果を生むようになってから、短いアニメーションクリップに移ります。

**実行には高性能なコンピューターが必要ですか？**
あるとかなり役立ちます。特に動画ではそうです。画像生成はより許容範囲が広いので、妥当な開始戦略は、インストールし、まず画像をテストし、自分のハードウェアがワークロードをどう処理するかを理解するまでクリップを短く保つことです。最新のGPUドライバーは、生のスペックと同じくらい重要です。

**マルウェアを避けるには、どこでArtCraftのダウンロードを入手すべきですか？**
常に公式ソースを使用してください。最新のビルドとドキュメントについては[ArtCraft公式サイト](https://getartcraft.com/)から始め、ソースコード、Issue、リリースノートについては[ArtCraft GitHubリポジトリ](https://github.com/storytold/artcraft)を確認してください。サードパーティのミラーサイトは、壊れた、またはバンドルされたインストーラーを入手してしまう最も一般的な経路であり、コミュニティの報告もそれを繰り返し裏付けています。
